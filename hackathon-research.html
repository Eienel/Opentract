Hackathon Research — Finding One to Win

Compiled from 4 parallel research agents · as of May 14, 2026 · for a 3-person team, strong general engineers, no dedicated GPU, can rent cheap cloud GPUs / use hosted APIs

TL;DR — the play

  1. Best pure-AI bet: Google Cloud Rapid Agent Hackathon — $60K across 6 small per-track pools, June 11 deadline, no GPU, no crypto.
  2. Highest ceiling (crypto, tight): Sui Overflow 2026 — $1M+ pool, has an AI-agent track, but submission ~May 23 and you'd learn Move fast.
  3. Watch & grab a spot: next Cerebral Valley "Built with Claude Code" (likely June) and the Global MCP Hackathon (Aug edition).
  4. How to actually win: stop building at ~70% of the clock, narrow scope to one demo path, record a scripted <3-min demo, target sponsor tracks not the grand prize.
  5. Best low-competition "hidden gems" (see §3): UNDP Crisis Mapping ($50K, ~385 solvers, Jun 23) · Convex & Resend ($5K, dozens of entrants, Aug 4) · Zindi (recurring cash ML challenges, global, small fields).

5 · How to Win — the playbook

The blunt judge consensus: a mediocre project with a great pitch beats a great project with a mediocre pitch.

What judges score

~4 axes: problem/impact, creativity, technical execution, presentation/demo.

Why projects lose

  • Overscoping — the #1 killer. A 3-month product crammed into 48h leaves nothing demo-able.
  • Weak/crashing demo — judges see dozens of projects; if yours isn't clear in 3 minutes the brilliance is invisible.
  • Failing baseline requirements — many submissions are DQ'd just for missing a required deliverable (video, repo link, sponsor tech).
  • Generic descriptions — judges explicitly penalize recycled ideas and vague writeups.

Project selection

  • Score ideas 1–5 on: demo-ability, story/personal pain point, technical depth, team passion. Pick the winner only if someone genuinely cares.
  • Demo-ability first: can a judge experience the magic in 30 seconds?
  • Avoid the thin API wrapper. Depth wins — multi-agent orchestration, real-time streaming, a real domain problem with measurable outcomes.
  • Useful + narrow beats novel + broad.

Time management (48h model)

  • Hours 0–2: lock the idea, write a tight 1-page PRD (also feeds your AI coding tools and prevents hallucinated implementations).
  • Hours 2–30: build the single demo path only. Hardcode, fake auth, skip DBs, run locally.
  • Hard stop at ~70% of the window. The last ~30% is only polish, demo video, and writeup — freeze the build, don't debug.
  • Use only tools you know cold. A hackathon is not when to learn a new framework.

Demo & submission — where points are won/lost

  • Demo video < 3 min, scripted, screencast with narration of the actual flow. Lead with the problem and a working result, not architecture.
  • Record a backup demo — never debug live.
  • Writeup: mirror the hackathon's stated judging criteria and inspiration language directly. Include the real repo.
  • Upload early — video processing can take hours; last-minute uploads cause DQs.
  • Prepare 3 pitch lengths: one sentence, one tweet, 2-minute full.

Using AI coding tools without making a mess

  • Start with the PRD/spec as shared context; let Claude Code work against it.
  • Build one vertical slice end-to-end first, then expand — don't scaffold everything broadly.
  • Small, reviewable commits; verify each feature works before moving on.
  • AI for boilerplate, UI scaffolding, glue code, demo script — humans on the core "magic" logic and integration.

AI/LLM-specific patterns

Overdone (won't win): yet another RAG chatbot, single-prompt wrappers, generic "chat with your X."
Winning in 2025–26: multi-agent coordination, autonomous agents with measurable results (ROI, win-rate, risk reduction), real-time streamed agent progress (SSE/WebSockets), full-stack execution tied to a specific domain.

Sponsor-track strategy

  • Sponsor prizes have less competition than the grand prize — easier ROI.
  • Design one project to qualify for 2–4 sponsor tracks at once — most teams don't think to do this.
  • Talk to sponsor reps during the event — they tell you what they want and often influence judging.
8-step checklist: (1) Read rules + judging criteria first, list every required deliverable. (2) Score ideas; pick demo-able + narrow + real problem. (3) Write a 1-page PRD. (4) Build one vertical demo path; hardcode the rest. (5) Stop building at 70% of the clock. (6) Record a scripted <3-min screencast + backup. (7) Write the submission echoing the criteria; upload early. (8) Design for 2+ sponsor tracks; chat up sponsor reps.
